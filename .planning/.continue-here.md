<completed_work>

- Resolved the pre-existing `ruff format --check` failure in `idm_heatpump/registers.py` (indentation-only; no schema change).
- Implemented `idm_heatpump/transport.py`:
  - `@runtime_checkable IdmModbusTransport(Protocol)` — lifecycle (`connect`/`close`/`connected`) + raw register words (FC03/FC04 reads, FC16 writes). Transports own no retry, lock, batching or write safety.
  - `_PymodbusTransport` — default adapter wrapping `AsyncModbusTcpClient` so the default path and injected transports are symmetric. Pymodbus unit-id param name (`slave` vs `device_id`) resolved once by the client and passed in.
  - `check_transport_response(result, address, *, operation)` — central device-response mapping: code 2 → `IllegalAddressError` (permanent), other errors → `ModbusException` (transient). Lazy import of `IllegalAddressError` avoids a load-time cycle with `client.py`.
- Routed `IdmModbusClient` through `self._transport`:
  - New keyword-only `transport: IdmModbusTransport | None = None` constructor param. `None` → default `_PymodbusTransport`; injected object must satisfy the protocol or `TypeError` is raised.
  - `_connect_internal`/`disconnect`/`_ensure_connected`/`force_reconnect`/`_require_client`/`_try_reconnect` delegate to `self._transport`.
  - `_read_registers`/`_write_registers` call `self._transport.read_*`/`write_*`; the requested-count invariant is checked client-side (transport-agnostic).
  - `_client` is now a property aliasing `_transport` (getter + setter) so the legacy `client._client = fake` test seam keeps working.
  - All API-owned logic (`_lock`, `_max_retries`, `_connection_suspect`, `_record_error_context`, `_retry_command`, batching, quarantine, model detection, write safety) unchanged.
- Updated `FakeModbusTransport` to model the protocol correctly: returns raw `list[int]` and raises `IllegalAddressError`/`ModbusException` instead of pymodbus-shaped response objects. Added `connect()`/`close()`.
- Exported `IdmModbusTransport` from `idm_heatpump.__all__` and pinned it in `tests/test_public_api.py`.
- Added `tests/test_modbus_transport.py` (24 tests): protocol satisfaction, constructor validation, injection routing (reads/writes/lifecycle/lock), legacy-compat equivalence, exception-code semantics (codes 5/6/10/11 transient, no-quarantine; code 2 permanent; code 6 retry-in-place not hard-reconnect), `check_transport_response` helper, default-transport legacy parity.
- Pinned the legacy `_client` property alias explicitly in `test_fake_modbus_transport.py`.

- Do not turn the existing protected subclass hooks into the public 1.0 contract. ✅ The four overrides (`_ensure_connected`, `_try_reconnect`, `_read_registers`, `_write_registers`) are now thin delegations to `self._transport`, not the contract.
- Do not add a hard API dependency on Home Assistant, `modbus-connection` or tmodbus. ✅
- Do not treat transient device response codes 5/6/10/11 as unsupported individual registers. ✅ Pinned by `test_codes_5_10_11_do_not_quarantine_registers` and `test_code_6_busy_is_transient_not_permanent`.
- Do not stack backend and API retries for server-busy code 6. ✅ Code 6 uses retry-in-place; `test_code_6_busy_is_retried_in_place_without_reconnect` pins that `transport.close` is not invoked.
- Do not claim a stable 1.0.0 is exclusively installable by Beta 2.
- Do not publish until both legacy Pymodbus and the real add-on transport adapter pass.
- Do not alter the register schema as part of the Ruff formatting repair. ✅
